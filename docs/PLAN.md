# 專案規劃（Project Lead）

## 目標
做一個類似 Lightsplit 的 LINE 分帳工具：群組裡就能記帳，也有獨立網站；手機優先、介面時尚好用；免費方案即可營運。

## 技術決策
| 項目 | 選擇 | 理由 |
|---|---|---|
| 前端 | 無框架 ES Modules + LIFF SDK | 不需建置、LINE 內開啟快、GitHub Pages 直接託管 |
| 後端 | Cloudflare Workers + D1 | 免費額度高、全球低延遲、可同時處理 API 與 LINE webhook |
| 身分 | LIFF ID Token，由後端向 LINE 驗證 | 不需自建帳號系統 |
| 金額 | 一律以基準幣別「最小單位整數」計算 | 避免浮點誤差，分攤餘數用最大餘數法 |
| 公費 | 視為虛擬成員 `__fund`，結算時併入保管人 | 公費現金實際在保管人手上，帳務上最直觀 |
| 分享到群組 | 優先 `liff.sendMessages`（以本人名義、不耗額度），其次機器人推播 | 符合「預設分享」又控制成本 |

## 角色與交付目標
各角色獨立完成工作，完成後由指定的驗證角色檢查，最後由 Project Lead 驗收。

| 角色 | 目標（交付物） | 完成定義 |
|---|---|---|
| 產品規格（PM） | 功能清單、資料模型、驗收標準 AC-01～AC-12 | 每個使用者需求都對應到可測的標準 |
| UX/UI 設計師 | 設計語彙、色彩字體、行動版版面、`web/css/app.css` | 390px 寬無水平捲動；觸控目標 ≥ 38px；深色模式；支援減少動態 |
| 演算法工程師 | `money.js`、`settle.js` | 分攤總和恆等於總額；結清筆數與暴力解一致 |
| 前端工程師 | `web/` 全部畫面與流程、示範模式 | 所有 AC 可在手機上完成 |
| 後端工程師 | `worker/`：API、D1 schema、LINE webhook | 權限、驗證、封存規則皆由伺服器把關 |
| DevOps | GitHub Actions（CI、Pages、Worker）、部署文件 | 從零照 README 可部署 |
| **QA 驗證員**（由 PL 指派） | 單元測試、API 整合測試、手機 E2E＋截圖審查 | 見 QA-REPORT.md |

## 設計語彙（UX/UI）
- 主視覺只有一個：**車票形狀的餘額卡**（打孔缺口＋虛線票根），呼應「一起出遊、一起分帳」。其他元素保持安靜。
- 色彩：Paper `#F2F4F7`、Ink `#18223A`、Cobalt `#2F54EB`、應收 `#0F8F63`、應付 `#D93A57`、Line `#DDE2EB`
- 字體：數字與品牌用 Bricolage Grotesque；中文用系統黑體（PingFang TC／Noto Sans TC），載入快。
- 版面：單欄、左對齊；重要動作放拇指區（右下「記一筆」、底部抽屜表單）。
- 刻意避開：奶油底＋襯線、全大寫小標、每張卡片同一種陰影。

## 驗收標準
| 編號 | 標準 |
|---|---|
| AC-01 | 在 LINE 群組內開啟、或用外部瀏覽器開啟同一網址，都能使用 |
| AC-02 | 紀錄可新增、修改、刪除；支出／轉帳／存入公費 |
| AC-03 | 預設 TWD；可選 15 種幣別，自動帶匯率且可手動調整 |
| AC-04 | 平分／自訂金額／依份數；自訂金額加總不符時不能儲存 |
| AC-05 | 結算給出最少轉帳筆數，套用後所有人歸零 |
| AC-06 | 每人可填匯款資訊，只有本人可改；結算頁可複製 |
| AC-07 | 團體與個人統計；匯出 CSV（Excel 中文不亂碼） |
| AC-08 | 可建立、切換、封存、刪除多個帳本 |
| AC-09 | 首次進入選擇身分，依 LINE 名稱推薦並帶入大頭貼；不能搶別人已綁定的 |
| AC-10 | 可分享邀請、可新增／移除成員（有帳目者改為停用） |
| AC-11 | 公費：存入、支出、保管人、餘額顯示並正確併入結算 |
| AC-12 | 新增／修改／刪除時可選是否分享到 LINE 群組，預設開啟 |
